两层架构设计指导

把“测什么、怎么评”和“怎么走、怎么采”彻底拆开。上层只表达计量意图，下层只兑现设备能力。复杂功能先定层，再定模块，最后才写代码。

L2 · 设备执行层

1. 为什么只分两层

三坐标上位机最容易做成“五层看起来很完整，实际每层都在碰机床”。真正稳定的产品，对外只暴露两层业务边界：

  • L1 回答计量问题：这个孔的位置度是否合格？基准怎么建？程序如何离线编？
  • L2 回答设备问题：测针从哪接近、以何速度触发、MCS 点如何采回、碰撞如何停。

专家口径

L2 内部可以有通信、运动学、测头、安全等子模块，但它们是L2 的实现细节，不得成为 L1 可直接调用的第三层。否则 GD&T 模块迟早会去拼 I++ 字符串，控制器适配迟早会去改评定公式。

两层能换什么

  • 换控制器：Renishaw UCC / 国产总线 / I++ DME，L1 不动
  • 换评定：ISO 1101 / ASME Y14.5，L2 不动
  • 换机型：桥式改龙门，只改 L2 运动学与工作空间
  • 离线编程机与联机测量机可共用 L1

两层不能省什么

  • 层间必须有版本化契约，禁止“顺手调一下底层”
  • 坐标系必须显式传递，禁止各层各自猜当前系
  • 补偿图版本必须随测点一起上行
  • 故障码分计量 / 设备 / 通信三类，禁止一个 error=-1

2. 分层边界：允许与禁止

L1 允许

  • 定义特征、构造特征、基准体系 DRF
  • 生成测量意图：期望点、法向、搜索距离、扫描策略
  • 最小二乘 / 最小区域 / 内外接评定
  • ISO 14405 尺寸、ISO 1101 / ASME 形位公差
  • 程序编辑、仿真回放、报表、SPC、权限
  • 消费 L2 能力矩阵，决定能否执行某策略

L1 禁止

  • 直接发轴运动、G 代码、控制器专有帧
  • 解析 EtherCAT / 串口 / UCC 报文
  • 实现伺服前瞻、加减速、look-ahead
  • 硬编码某机型杆长、光栅方向、测座零位
  • 在 UI 线程里等触发中断
  • 把机床误差图当“评定修正值”偷偷改结果

L2 允许

  • 机型运动学（含测座 A/B、转台、关节臂）
  • 21 项几何误差 / 体积补偿 / 温度补偿
  • 接近-触发-回退、扫描路径插补、碰撞盒
  • 测针库、等效直径、弯曲与测座角补偿
  • 命令队列、心跳、看门狗、断线策略
  • 上报 MCS/PCS 原始点、力/偏转、时间戳

L2 禁止

  • 理解图纸公差、基准、位置度公式
  • 决定“下一个测哪个特征”（除非执行已下发任务）
  • 生成质量报告或合格/不合格判定
  • 在通信线程里做重拟合
  • 因评定失败而自动改速度或改测点（须回 L1 决策）
  • 把 UI 字符串当协议字段

3. L1 计量应用层设计

L1 的产品语言是特征与公差，不是轴和脉冲。设计时先建“测量意图模型”，再映射到 L2 任务。

3.1 核心对象

Part / Setup

职责 零件、夹具、批次、温度名义值

检视 是否与设备序列号解耦

Feature

职责 点 / 线 / 面 / 圆 / 柱 / 锥 / 球 / 曲线 / 曲面

检视 名义、公差、采样策略分离存储

DRF / Alignment

职责 3-2-1、RPS、最佳拟合

检视 约束、权重、失败回退显式化

Program

职责 顺序、循环、分支、托盘

检视 可离线仿真，不依赖联机

Evaluator

职责 拟合与 GD&T

检视 算法版本可追溯，异常点策略可配置

Report / Trace

职责 结果、测点、补偿版本、操作者

检视 能复现当次测量，而不是只留最终数

3.2 坐标系纪律

上位机里至少同时存在四套系，L1 必须显式命名，禁止“当前坐标系”这种隐式全局：

  1. MCS 机床系：L2 主场，补偿后的机器坐标
  2. PCS 零件系：L1 主场，找正后的工作坐标
  3. CAD 模型系：离线编程与法向来源
  4. Tool 测头系：测针球心、测座角、星形针

找正矩阵只由 L1 计算，经契约下发给 L2 作为工作偏置。L2 可用它把 MCS 转成 PCS 上报，但不得自行改找正。扫描过程中若发现漂移，只上报事件，由 L1 决定是否重找正。

3.3 测量意图，不是点列

L1 下发应优先是策略，而不是写死的机床点：

  • 圆：圆心名义、直径、采样数、均匀角、内/外、拟合方法
  • 面：边界、网格、法向、滤波波长
  • 扫描曲线：路径参数、节距、速度上限、力控窗口

L2 负责把策略展开成可执行路径。这样换针、换测座角、加安全平面时，不必改零件程序语义。

L1 模块划分建议
  • 程序与配方：编辑器、版本、权限、电子签名
  • CAD/PMI：名义几何、法向、GD&T 语义导入
  • 找正引擎：3-2-1 / 最佳拟合 / RPS / 逐级约束
  • 评定引擎：尺寸、形位、轮廓、滤波、粗差
  • 结果与 SPC：批次、Cp/Cpk、报表模板
  • 仿真视图：只读消费 L2 运动学模型，不控实机

4. L2 设备执行层设计

L2 对外是一台“有能力的测量设备”，对内才是控制器、测头和误差图。产品上应对齐 I++ DME 的思想：能力查询 + 任务执行 + 异步事件，即使实际协议不是 I++。

4.1 能力矩阵（先问再做）

  • 运动：轴数、工作空间、最大速度/加速度、转台
  • 测头：触发 / 扫描 / 光学；测座索引或连续；换针
  • 安全：软限位、碰撞源、过行程复位方式
  • 补偿：几何误差图、温度通道、是否已使能
  • 流式：扫描点频率、是否带力/偏转

L1 在生成程序或切策略前必须读能力。没有扫描头就不要下发扫描任务；没有转台就不要假设 C 轴。

4.2 内部子域（仍属 L2）

运动学

做什么 关节↔笛卡尔、测座、转台

不泄漏给 L1 DH 参数、零位脉冲

路径与碰撞

做什么 安全平面、回退、盒体 / 网格碰撞

不泄漏给 L1 插补周期、前瞻缓存

测头服务

做什么 校准、等效直径、弯曲、星形针

不泄漏给 L1 触发板阈值寄存器

补偿服务

做什么 21 项、体积图、温度、力变形

不泄漏给 L1 图文件二进制布局

设备适配

做什么 I++ / 私有以太网 / 现场总线

不泄漏给 L1 报文、重试字节

安全监护

做什么 急停、看门狗、工作空间、互锁

不泄漏给 L1 I/O 点表

4.3 采集质量必须上行

每个点至少带：坐标、所在坐标系、测针 ID、测座角、补偿图版本、触发/扫描标志、预行程或偏转、时间戳、质量位。缺质量位的点，L1 不得当合格数据做精密评定。

5. 层间契约

两层只通过稳定 API 对话。建议命令下行、事件上行，全部异步，禁止 L1 阻塞等待伺服周期。

↓ L1 → L2　GetCapabilities()　SetActiveTool(tool)　SetWorkOffset(T_pcs)　Probe(strategy)　Scan(strategy)　MoveClearance()　ChangeTool()　Pause/Resume/Abort　Home()
↑ L2 → L1　PointBatch　ScanChunk　StateChanged　ToolChanged　Fault(estop/collision/overtravel/comm)　CompensationContext　Progress

5.1 契约设计硬规则

  1. 所有几何量带单位与坐标系 ID，禁止裸 double x,y,z。
  2. 任务有唯一 jobId，事件必须带回，禁止靠时序猜测。
  3. 失败分：可重试通信、需复位设备、需 L1 改策略三类。
  4. L2 状态机对外只有：空闲 / 运动 / 探测 / 扫描 / 故障 / 急停。
  5. 补偿使能状态变化视为配置变更，正在运行的任务应拒绝或显式作废。
  6. 仿真模式走同一契约，仅 L2 后端换成虚拟设备。

5.2 一次圆孔测量的正确流向

1 L1 读取特征：内圆、8 点、LS 拟合、位置度相对 A|B|C
2 L1 查 L2 能力与当前测针；生成 ProbeCircle 策略（含搜索方向与安全高度）
3 L2 展开路径、碰撞检查、下发控制器；采回 MCS 点并附质量与补偿版本
4 L2 按当前 WorkOffset 可选转换为 PCS 后批量上行
5 L1 拟合、评定、记录原始点与结果；不合格不回写 L2 去“再快一点”

6. 运行时、安全与计量合规

6.1 线程模型

  • UI 线程：只渲染与交互，零设备 I/O。
  • L1 工作线程：程序解释、评定、报表。
  • L2 设备线程：协议、队列、状态机。
  • 采集回调：尽快入队，重计算放到 L1。

6.2 安全底线（L2 主责，L1 配合）

  • 急停与碰撞：L2 立即停，再通知 L1；L1 不得“先问用户再停”。
  • 程序运行中禁止改补偿图、改测针定义、改软限位。
  • 手动操纵杆与自动程序互斥。
  • 工作空间、测针球、工件/夹具模型必须参与碰撞，缺模型要降级为保守盒并告警。

6.3 计量可追溯

  • ISO 10360 验收/复检流程走正式程序，结果进追溯库。
  • 测针校准、温度、误差图版本、软件算法版本写入当次测量包。
  • 评定算法变更必须升版本，旧零件程序默认绑定旧算法或明确迁移。
  • 原始点与评定结果一起存，禁止只存“合格”。

8. 常见反模式

上帝 UI

界面按钮直接写控制器命令。结果是演示很快，机型一换、安全一加就全面返工。

评定里“修一点机床误差”

把体积补偿、温度、测针弯曲塞进 GD&T。计量语义被污染，验收与日常测量会对不上。

全局当前坐标系

各模块读同一个可变矩阵。异步扫描块一乱序，点就评到错误的系里。

静默降级

没有扫描头就改成触发点、碰撞模型缺失就关碰撞。现场表现为“有时准有时撞”。

假三层、真两摊

文档写了领域层，代码仍是“界面 ↔ 通信”。检视时以依赖方向和搜索协议字符串为准，不以 PPT 为准。

9. 落地顺序

  1. 冻结两层职责表与禁止清单（本文第 2 节）。
  2. 先定义契约与状态机，再写功能。
  3. 用虚拟设备打通：程序 → 任务 → 假点 → 评定 → 报表。
  4. 接入一种真实控制器，补齐安全与补偿上下文。
  5. 用标准球/标准量块做 L1 金样 + L2 实机对照。
  6. 再扩展扫描、转台、光学；每增能力只改 L2 能力矩阵与执行器。

评审时一句话标准

如果一个需求既能说成“公差/程序/报表”又能说成“轴/测头/报文”，就还没分层。先拆成 L1 意图 + L2 能力，再估工作量。
